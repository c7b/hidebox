# hidebox (repository codename mutis): architecture for this audit run

Snapshot: origin/main 460a389, read-only. Paths below are repository-relative.

1. **Product, principals, protected resources.** A client-side-encrypted drive and file-sharing service on the Tari Ootle testnet. The browser encrypts every file (AES-256-GCM, 4 MB chunks, Padmé padding) and keeps the file key, the link secret after `#`, passwords and the drive seed; the server stores ciphertext, SHA-256 verifiers (access token, link proof, manage token, login key, claim token, session token), padded sizes and exit rules. Principals: anonymous visitor (IP key, PoW); link holder (`X-Mutis-Access`, plus `X-Mutis-Link` for link+password); password guesser; uploader with a manage token (`X-Mutis-Manage`); holder of an `upload_id`; drive/locker session (`Authorization: Bearer`, 30 days, 7 idle); drop owner and drop submitter; paid-link buyer (`X-Mutis-Claim`) and seller (session, sealed sales view key); judge-pass holder (`X-Mutis-Judge`); the canary (`X-Mutis-Canary`); the chain worker and its Node sidecar (user `drive`, shares the SQLite DB with the API, reaches walletd); the operator (`sudo mutis-admin`); the `build` user. Protected: other users' ciphertext and metadata, link/claim/ticket authority, `server_half` of paid links, sellers' sealed view keys, the sponsor/demo wallet's testnet funds and the daily budgets, disk and pack capacity, visitors' IP privacy (no IP on disk), the release integrity of served code.
2. **Comparable baseline.** No comparable product is named in source; the "key in the URL fragment, server holds ciphertext" pattern is the one of one-time encrypted share services. Calibration only.
3. **Stack and deployment.** Python 3.13 stdlib `ThreadingHTTPServer` API (`server/mutis/api.py`, loopback 127.0.0.1:8787 only) with SQLite (`server/mutis/schema.sql`, migrations); chain worker `server/mutis/chain_worker.py` with walletd JSON-RPC (`walletd.py`), public indexer client (`indexer.py`) and a Node sidecar (`web/app/sidecar/sidecar.mjs`, Node permission model, vendored ootle-wasm 0.46.0 pinned by hash). Browser app: vanilla ES modules (`web/app/lib`, `web/app/ui`), WebCrypto, Trusted Types; static site `web/site`, `web/shared`. Caddy (`deploy/caddy/Caddyfile`): TLS, CSPs (site, app with `require-trusted-types-for`, API `sandbox`), 5 MB body cap, `X-Real-IP {remote_host}`, no access log. systemd units (`deploy/systemd`), users `mutis` (API), `drive` (worker, sidecar, walletd), `build`, `caddy`; ufw owner-match guards on loopback 5100/8787/18143 (deployment fact). Build `tools/build.py` (SRI, hash manifest), `tools/verify-deploy.py`. Offline: server suite and `server/tests/harness.py` `Stack` (real API on loopback with FakeChain/FakeIndexer/FakeWalletd/fake sidecar), `server/bin/mutis-api --dev`, `deploy/tests`, `web/app/tests/node-run.mjs` with `fake-api.js`. Not available: Chromium, Rust/wasm32, Caddy, walletd. Live config (`/etc/mutis/mutis.toml`), DB feature overrides, ufw rules and the installed Caddyfile are deployment facts.
4. **Entry surfaces and paths.** All routes: `server/mutis/router.py` → `server/mutis/handlers/*.py`; parsing `http_util.py` (64 KiB JSON, Content-Length only, path-param regexes), dispatch `api.py` (per-IP limiter, in-flight caps, Origin check on non-GET when present, 16 KiB headers). Key flows: uploads (`handlers/uploads.py` → `storage.py` blobs, `quota.py`, `lanes.py`, `packs.py` brakes); links (`handlers/shares.py`: create/status/peek/open/stored/patch/manage/revoke; password backoff; tickets → `handlers/blobs.py`); folders/tree/trash (`handlers/folders.py`, `tree.py`, `items.py`); drive (`handlers/auth.py`, `auth.py`, `handlers/me.py`); pay to open (`handlers/pay.py`, `sales.py`, worker `verify_sales`); packs/invoices/demo pay/sponsor (`handlers/invoices.py`, `payments.py`, `budgets.py`); courier/drops/jobs (`handlers/courier.py`, `handlers/drops.py`, `jobs.py`); indexer proxy and direct-send submit (`handlers/chain.py`, `cbor.py`, `mirror.py`); SealLog/canary/stats/abuse (`handlers/seallog.py`, `seallog.py`, `handlers/canary.py`, `handlers/stats.py`, `handlers/abuse.py`); admin CLI `admin.py`; cleanup `cleanup.py`. Browser sources: URL fragment (`web/app/lib/links.js`), API JSON, decrypted metadata from senders (names, types), chain memos and the UTXO mirror scanned in the browser (`scan.js`, `courier.js`), zip/EXIF/filetype (`zip.js`, `exif.js`, `filetype.js`), previews (`preview.js`), downloads (`download.js`), the drop widget (`drop-widget.js`, `ui/widget.js`), browser storage (`store.js`, `idb.js`, `identity.js`).
5. **Trust boundaries and strongest visible control.** Internet → Caddy → API: Caddy rewrites `X-Real-IP`; API trusts it only from a loopback peer (`ipkeys.py`). Visitor → link: access-token hash compare (`codec.equal`), link proof, PoW/backoff for passwords, views and expiry in one transaction. Owner actions: `require_owner` (session owner OR manage token OR canary token) and `own_item` for drive routes. Ticket → bytes: bearer ticket hash, TTL, byte cap, folder `tree.within` re-check. Buyer → `server_half`: claim token hash + release gate (`sales.releasable`). API → worker: shared DB and jobs table; worker re-validates payloads (`jobs.py`), budgets (`budgets.py`). Worker → walletd: loopback port guarded by uid (deployment). Browser: CSP + Trusted Types + `dom.js` (no HTML sinks), previews allowlisted, downloads as octet-stream. Release: SRI + manifest + verify-deploy.
6. **Starting paths.** `server/mutis/api.py`, `router.py`, `http_util.py`, `handlers/`, `auth.py`, `items.py`, `tree.py`, `sales.py`, `payments.py`, `jobs.py`, `chain_worker.py`, `cleanup.py`, `admin.py`; `web/app/lib/`, `web/app/ui/`, `web/app/sidecar/`; `web/site/js/`; `deploy/caddy/Caddyfile`, `deploy/systemd/`, `deploy/scripts/`; `tools/build.py`, `tools/verify-deploy.py`.
7. **Prior coverage.** No prior run of this skill (no ledger). Prior non-ledger evidence: `docs/threat-model.md`, `docs/review/upload-safety-1.md` (F1–F4, fixed), the `REVIEW-devil.md` files (server H1–H4, M1–M8 with builder responses), `docs/review/fix-log.md`. Known accepted residuals (do not re-report as new without new evidence): slow online guessing of weak password-only links; a botnet or an IPv6 /32 passing per-network brakes; in-memory counters reset on restart; the server could serve malicious JavaScript; metadata listed on `/made#who`; the reporter may include a link key in an abuse report (stated).
8. **Companions selected.** WEB-PROTOCOL-AND-AUTH (custom HTTP server behind a proxy, forwarded-IP trust, bearer/manage/claim/judge credentials, sessions); CLIENT-SIDE (SPA rendering sender- and chain-controlled data, storage, workers, previews); DATA-ISOLATION-AND-LIFECYCLE (per-drive ownership, links, tickets, trash/delete/revoke, backups); RESOURCE-EXHAUSTION-AND-AVAILABILITY (uploads, disk, PoW, budgets, quotas, pre-auth work); PROTOCOLS-RPC-AND-MESSAGING (API↔worker jobs table, indexer and walletd responses, sidecar JSON lines, submit-proxy envelope parsing); CLOUD-AND-DEPLOYMENT (systemd, ufw, Caddy, provisioning, runtime config); SUPPLY-CHAIN-AND-RELEASE (vendored wasm, build/SRI/manifest, deploy/activate/rollback, notarization). Excluded: MEMORY-SAFETY-AND-BINARY (no native code in scope; the vendored wasm runs inside V8's sandbox and is pinned), AI-AND-LLM (no model in the product), DESKTOP-MOBILE-AND-LOCAL-IPC (no native app; the sidecar's stdin/stdout is covered under protocols).
