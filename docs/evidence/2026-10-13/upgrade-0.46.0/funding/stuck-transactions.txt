0.46.0? Read 2026-10-13 ~19:10 UTC in the source at the tag (cc8a83bc, fetched with gh api from the
jarvis box, as data) and on ultron (read-only). Answer: no; they were left as they are.

== What could "cancel" one
  applications/tari_walletd/src/server.rs (the JSON-RPC table): the transactions.* methods are submit_instruction,
  submit, submit_dry_run, detect_inputs, submit_manifest, publish_template, get, get_result, wait_result,
  list|get_all. None cancels, abandons or rescans. The only "cancel" in the table is confidential.cancel:
  handlers/confidential.rs:280-289 handle_cancel_transfer(ProofsCancelRequest { proof_id: WalletLockId })
  → locks_api().release_lock(lock_id), documented for a confidential transfer proof.
  storage_sqlite/src/writer.rs:2534-2541 locks_release(lock_id) = confidential_outputs_release_by_lock_id
  + stealth_outputs_release_by_lock_id (deletes the LockedUnconfirmed outputs the lock created:
  ../walletd.txt point 5) + vaults_release_lock_revealed_funds + locks_delete. It never touches the
  transactions table.
  sdk_services/src/transaction_service/service.rs:464-503 check_pending_transactions: every poll (5 s,
  poll_interval) reads transactions with status Pending (transaction_api.fetch_all(Some(Pending))) and asks
  the indexer for each; a 404 is "Transaction result not found … Will check again later"
  (sdk/src/apis/transaction.rs:233-243) and the status stays Pending. Locks play no part in it.
  The CLI (cli.rs:158-195): run, create-account, new-viewable-balance-key, seed-words, reset (wipes local state).
  So: (1) releasing a lock would not quiet anything, since the poll follows the transaction's status,
  which only a result from the network changes; (2) for the sponsor's 2749858a… it would delete the change
  3ee453ab… (8,851.452 tTARI, the output we still want back); (3) no RPC lists lock ids, so it couldn't
  even be aimed without reading the store by hand, which the brief forbids.

== What cancelling would do to the 20 service manifests' outputs (read-only check, wsnap.py -v)
  service's stealth outputs: Spent 9, Unspent 1 (5a4710af…, the relief's change); none LockedUnconfirmed.
  The 20 manifests (checkpoints #141 to #156 and four notarization attempts) pay their fee from
  service's public vault with pay_fee (setup-accounts.md §4), so they hold no stealth change; whatever
  vault lock they hold is not what keeps them polled. They are committed on chain (../chain.txt), so
  nothing is lost by leaving them.

  is Tari's (a walletd that gives up on a result that is gone), not ours.
